# SSH Brute-Force & Credential-Stuffing Detector

An interactive Python tool that parses SSH authentication logs and flags brute-force attacks,
credential-stuffing attempts, and likely account compromises using sliding-window detection,
visualized in a Streamlit dashboard.

## What the App Does

- **Log parsing.** A regex-based parser reads standard `sshd` auth log lines — `Failed password`,
  `Accepted password`, and `invalid user` variants — into a pandas DataFrame.
- **Three detection heuristics**, each backed by an O(n) sliding time window:
  - *Brute force* — repeated failed attempts against a single account from one IP inside a
    configurable time window.
  - *Credential stuffing* — failed attempts from one IP spread across many distinct usernames,
    the bot-style account spraying pattern.
  - *Likely compromise* — a successful login immediately following a burst of failures from the
    same IP.
- **Interactive dashboard.** Sidebar sliders adjust the threshold and window for every detector,
  alongside summary metrics, a failed-login timeline, and top offending IPs and usernames. You can
  upload your own log file or use the bundled synthetic sample, and export flagged IPs to CSV.

## How Detection Works

Each detector scans failed-login timestamps for a given IP (and username) with a two-pointer
sliding window, finding the maximum number of events inside any window of length `N` minutes in
O(n) time per group. If that count exceeds the threshold, the IP/user pair is flagged.

This mirrors how real detection rules are usually written — "more than 10 failed attempts in
5 minutes" — and the sliders make the tradeoff visible. The sample data includes a deliberately
"low and slow" attack that slips past the default settings and only gets caught once the window
is widened.

## Technical Notes

The project runs on synthetic logs generated by `generate_logs.py`, which injects the attack
patterns into an otherwise ordinary `sample_auth.log`, so the detectors can be demonstrated
without data from a real compromised host. Parsing, detection, and the dashboard are kept in
separate modules (`log_parser.py`, `detector.py`, `dashboard.py`) so the detection logic stays
independent of the UI.
